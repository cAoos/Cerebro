# 🧑‍💻 Coding agents en Salesforce

Un **coding agent** es un agente de IA que **escribe código**: genera código, queries y archivos de configuración a partir de una **conversación en lenguaje natural**. Ya no hace falta aprender primero las herramientas y lenguajes de cada entorno.

Desde **Claude Code, Cursor o Windsurf** se conecta de forma nativa a las APIs y MCP servers de Salesforce, sin aprender un IDE nuevo: **+30 coding skills** y **+60 herramientas MCP**, heredando seguridad, permisos y flujos (ver [[🧳 Headless Toolkit]]).

## 🧩 Qué necesita además del LLM
La inferencia sola **no basta**. Un coding agent conectado a una base cruda no sabe que el cliente tiene una **escalación abierta**, una **renovación en 30 días**, un **SLA vencido** y un dueño de la relación amigo de su CFO. Ese contexto vive en Salesforce.

- 🧠 **Contexto**: **Data 360 se expone como API, herramienta MCP y comando CLI** (ver [[☁️ Data 360 para agentes]]).
- 🔁 **Flujos** y 🛡️ **confianza** heredados de la plataforma.
- 📱 **Capa de engagement**: la **Headless Experience Layer (HXL)** pinta la interacción nativa en Slack, voz, WhatsApp…

> ⚠️ Ojo de examen: lo que separa a un coding agent que **escribe código** de uno que **entiende el negocio** es el **contexto de Salesforce** (Data 360), no el modelo.

Las capacidades headless usan: herramientas MCP y coding skills · una nueva capa de experiencia (HXL) · herramientas para **controlar cómo se comportan los agentes en producción**, antes y después del lanzamiento.
